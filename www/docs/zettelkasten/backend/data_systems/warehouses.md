# warehouses

A **data warehouse** organizes integrated data for analytical queries, reporting, and business intelligence. It commonly stores curated tables with defined schemas.

## Strengths

- Supports repeatable analysis over shared, cleaned datasets.
- Uses schemas and governance to make data easier to interpret.
- Often optimizes storage and execution for scans and aggregations.

## Costs

- Ingestion and modeling add delay before data becomes available.
- Schema changes and data preparation require ownership and maintenance.
- Cost and performance depend on data volume, query shape, and platform design.

Warehouses can store semi-structured data on modern platforms. Their contrast with [[lakes]] is about data management and access patterns, not a strict file-type limit. [[lakehouse]] architectures combine selected properties of both.
